# 现役实施计划

本目录保存**正在执行、已经获准但尚未完成**的短期实施计划；完成计划只允许在同一次交付的复核/纳入 Git 窗口短暂保留，随后删除。它不是第二份项目状态，也不保存产品定义；当前阶段仍看根目录 `README.md`，产品合同仍看 `DESIGN.md`。

## 当前计划

- 当前无现役实施计划。

## 每份计划必须回答

1. **为什么现在做：** 当前证据、问题影响和不做的后果。
2. **改什么、不改什么：** 文件/模块范围、外部系统和数据边界。
3. **依据与拍板：** 哪些来自文献、标准或已有代码，哪些是本项目权衡。
4. **实施顺序：** 每一步的输入、输出、依赖和停止条件。
5. **验收与回滚：** 自动证据、人判边界、失败时如何退回。
6. **失效条件：** 什么变化会让这份计划必须重审，而不是继续照旧执行。
7. **生命周期：** 状态、创建日期、最后复审日期和下一次复审截止。

## 生命周期与清理

计划状态只有四种：

- `proposed`：已写清，等待授权或前置证据；
- `active`：正在实施；
- `blocked`：外部条件明确缺失，并写明恢复条件；
- `complete`：仅用于完成变更当次的收口，不能长期留在本目录。

计划完成或失效时，在同一次变更中执行：

1. 把仍然有效的产品决定写回 `DESIGN.md`，架构事实写回 `docs/architecture.md`，测试规则写回 `docs/testing.md`；
2. 更新 `README.md` 的当前阶段和下一行动链接；
3. 从本索引移除并删除计划文件。Git 历史承担一般历史追溯，不另建长期 `archive/`、`done/` 或 `old/`；
4. 若确有审计、数据迁移或难回滚决策需要长期保留，改写为独立决策/证据记录，并说明保留义务；不能原样保留实施计划冒充现状。

每次修改 `README.md` 当前阶段、开始新主题分支或交付一个计划切片时，都要复审本索引。超过“复审截止”仍未更新的计划视为失效：先停止按它实施，核对当前代码和产品决定后再续期、改写或删除。

当前不增加自动过期脚本。升级触发条件是同时存在 3 份以上现役计划，或连续两次发现过期计划仍被引用；在此之前用文档评审和 Git diff 管理，避免为了一个计划目录先造治理系统。
